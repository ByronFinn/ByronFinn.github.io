# 接码平台体验分享-无广告纯享版


注册各种服务如GPT/CLAUDE/TG等需要一个能收验证码的号，但又不想拿自己手机号填。这类需求催生了一批接码平台，有的免费、有的付费、有的面向开发者。以下是我实际用过的四个，截止 2026 年 5 月 20 日都还能正常访问。平台状态随时可能变化，建议用之前自己先打开看看。

## ZUSMS：中文用户最顺手的免费选项

网站：<https://www.zusms.com/>

ZUSMS 是四个里面唯一有完整中文界面的免费接码平台。覆盖 20 个国家，包括美国（24 个号）、英国、香港（16 个号）、中国大陆（8 个号）、加拿大、日本、韩国、新加坡等。

用法很简单：选国家 → 挑一个在线的号 → 复制到需要验证的地方 → 回来看收到的短信。全程不用注册。

几个实际感受：

- 号码状态分"在线"和"离线"，在线的才能收到短信。如果试了一个号收不到，换一个或者换个国家试试，有些平台会屏蔽虚拟号码段
- 所有短信是公开可见的，任何人都能看到同一个号收到的内容。所以只适合收一次性验证码，别拿来接收任何跟钱或隐私相关的东西
- 不支持发短信，只收

适合的场景：注册一个不太重要的服务，收个验证码就走。

## eSIM Plus：国家覆盖最广的免费方案

网站：<https://esimplus.me/temporary-numbers>

eSIM Plus（临时号码页面）提供 33 个国家的免费临时号码，国家列表比 ZUSMS 多了不少，包括一些小众选项：爱沙尼亚、芬兰、以色列、立陶宛、荷兰、瑞典、瑞士等。

号码更新比较频繁，首页会标注每个号码"added X hours/days ago"。但也因为更新快，今天能用的号明天可能就没了。

几个需要注意的点：

- 他们自己也很直白地列了限制：号码公开无隐私、不保证可用性、部分 App 会屏蔽、数据不保留
- 有付费的私人虚拟号码选项，但免费层足够应对大多数一次性验证场景
- 界面是英文的

和 ZUSMS 相比，如果你需要一些冷门国家的号码（比如注册某个只接受特定国家手机号的服务），eSIM Plus 的选择更多。

## httpSMS：开发者的玩具

Sandbox：<https://sandbox.httpsms.com/>

httpSMS 跟前面两个不太一样。它本质上是一个把 Android 手机变成 SMS 网关的开源项目（GitHub: NdoleStudio/httpsms），核心功能是让开发者通过 API 收发短信。Sandbox 是它提供的一个免费测试环境，给一个美国号码 `+1 281 777 4568`，可以无限接收短信，但 24 小时后消息会被清除。

适合的开发场景：

- 你在写一个需要 SMS 验证的功能，想本地测试一下完整流程
- 需要一个稳定的 webhook 接收 SMS
- 想自建 SMS 网关而不是依赖第三方服务

httpSMS 本身免费，开源，支持端到端加密（AES-256）。如果需求量大，有 Pro 付费方案。它还支持 Zapier 集成、批量短信（CSV/Excel 导入）、发送频率控制等功能。

不过 Sandbox 的号码是固定的，所有人在用同一个号，所以它更像是开发调试工具，不是通用接码平台。

## Twilio：正儿八经的生产方案

网站：<https://www.twilio.com/en-us>

Twilio 不是传统意义上的"接码平台"。它是一个完整的通信 API 平台，覆盖 SMS、语音、邮件等通道。你可以在上面购买一个真实的手机号，然后通过 API 或控制台收发短信。

为什么也列在这里？因为如果你的需求不是"收个验证码就走"，而是"我需要一个长期可用的号码来收发短信"，Twilio 是最稳妥的选择。

- 按量付费，有免费试用额度（注册时需要绑卡或验证）
- 号码是你独占的，不存在公开共享的问题
- API 文档完善，SDK 覆盖主流语言
- 全球号码可购买

缺点也很明显：要花钱。如果你只是偶尔收一个验证码，杀鸡用牛刀了。

## 怎么选

四个平台对应三个层级的需求：

1. **收个一次性验证码**：ZUSMS（中文界面顺手）或 eSIM Plus（国家覆盖更广）
2. **开发调试 SMS 功能**：httpSMS Sandbox
3. **需要长期独占号码**：Twilio

最后重复一遍：免费平台的号码是公开共享的，任何人都能看到收到的短信内容。不要用来绑定银行、主力邮箱、社交媒体主号等任何重要的东西。用来注册一个临时需要手机号的服务，收完验证码就走，这是正确的用法。

以上信息截止 2026 年 5 月 20 日。这类平台状态变化很快，用之前建议先打开网站确认一下还能正常访问。
